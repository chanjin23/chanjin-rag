## 3. 결정 사항과 이유

- 의존성: `sqlalchemy[asyncio]`(2.1.8 설치됨), `alembic`(1.20), `pgvector`(HALFVEC 타입) — backend/pyproject.toml.
- 상태 값: PG 네이티브 enum 대신 `sa.Enum(native_enum=False, create_constraint=True, values_callable=값)` → varchar(32) + CHECK `ck_<table>_<col>`. 값 추가 시 ALTER TYPE 불필요.
- `jobs.status` 값은 TRD에 없어 `queued`/`running`/`done`/`failed`로 정함(버전 바뀌어 결과 버림도 done). `jobs.priority`는 timestamptz(파일 mtime). TRD 5.1에 반영.
- `chunks.filename` 컬럼 추가(TRD에 없던 비정규화, TRD 5.1에 반영): pg_search BM25 색인은 한 테이블 컬럼만 색인 가능 → 파일명 검색용 사본. 파일 이동 시 함께 갱신해야 함.
- BM25 색인(pg_search 0.26.5 문법, TRD 5.4에 반영): `USING bm25 (id, (bm25_text::pdb.whitespace), (filename::pdb.simple), (heading_path::pdb.simple))`. 0.26부터 `key_field` 불필요(첫 컬럼이 키, 주면 경고). `pdb.simple`은 `_`·`.`에서 자르고 소문자화. 같은 트랜잭션 안의 미커밋 행도 `@@@`로 검색됨(테스트에서 확인).
- HNSW: `m=16, ef_construction=64`, halfvec(EMBED_DIM). 모델과 마이그레이션 모두 `get_settings().embed_dim` 사용(마이그레이션 실행 시점 값).
- 경로 키: `make_path_key` = NFC → lower → NFC. `Document`의 `@validates("path_key")`가 넣는 값을 자동 정규화, `ext`는 소문자화. DB는 unique 제약(정규화 CHECK는 Python/PG lower 차이 위험 때문에 두지 않음).
- `sync_config`: id smallint PK + CHECK(id=1). 초기값 roots `["C:\Chanjin\dev"]`, excludes = TRD 6.1 기본 제외 7개, max_file_mb 10.
- `query_logs.message_id`는 NULL 허용(평가 질의 대비), 대화 삭제 시 CASCADE. `feedback.rating` CHECK IN (-1,1). 문서 삭제 시 sections·chunks·jobs CASCADE.
- 세션·토큰 해시: String(64) 16진수.
- `alembic.ini`는 ASCII만(Alembic이 locale 인코딩=cp949로 읽어 한글이면 UnicodeDecodeError). 마이그레이션 docstring 첫 줄도 ASCII(콘솔 출력).
- env.py: 동기 엔진(psycopg)으로 실행. `app.db.migrate.include_name`(모델에 없는 테이블은 반영 안 함 — ParadeDB 이미지의 PostGIS 테이블), `include_object`(`ix_chunks_bm25` 비교 제외). `alembic check`·`test_models_match_migration`이 같은 필터 사용.
- ParadeDB 이미지 template1에 vector, pg_search, postgis 등이 이미 있음. 마이그레이션은 `CREATE EXTENSION IF NOT EXISTS`만 하고 downgrade는 확장을 지우지 않음.
- 테스트 DB 공유: pytest 시작 시 `migrated_db`가 base→head로 비우고 다시 만듦(E2E가 남긴 데이터 제거). `test_upgrade_then_downgrade`는 같은 DB에서 내렸다 올리고, 픽스처가 끝에 항상 head로 되돌림.
- async 테스트: psycopg async는 Windows Proactor 루프에서 안 돼 conftest 맨 위에서 `WindowsSelectorEventLoopPolicy` 설정. 테스트 엔진은 NullPool(테스트마다 루프가 달라서).

## 6. 알려진 문제·막힌 점 / 다음 작업에 넘길 것

- (T02 등 DB를 쓰는 API 작업) psycopg async는 Windows ProactorEventLoop에서 안 됨. uvicorn은 Windows에서 `--reload` 없이 띄우면 Proactor를 씀(E2E 명령이 그렇다) → Selector 루프로 띄우는 방법 필요(예: uvicorn `--loop` 사용자 팩토리 또는 진입 스크립트에서 정책 설정). 앱에서는 `app.db.engine.get_session`(FastAPI 의존성), `dispose_engine()`(종료 시)을 쓰면 됨. 테스트는 conftest의 `session`(async, 롤백) 또는 `db`(psycopg 동기) 픽스처.
- E2E 백엔드는 이미 `rag-backend migrate` 후 기동하므로 테이블이 있음. E2E는 pytest와 같은 테스트 DB를 씀(pytest가 시작 시 비움). E2E끼리 데이터가 남으니 필요하면 global-setup에서 정리.
- 스키마를 바꾸는 작업은 새 리비전(`0002_…`)을 추가(`cd backend && uv run alembic revision --autogenerate -m …` 후 검토). `test_models_match_migration`이 모델·마이그레이션 차이를 잡음. BM25 색인을 바꾸면 `UNCOMPARED_INDEXES`와 마이그레이션을 직접 고칠 것.
- T05(청킹·토큰화)·T06(색인 작업): 청크 저장 시 `chunks.filename`에 문서 파일명 복사. T09: 파일명·제목 검색은 `filename @@@ …`, `heading_path @@@ …`(simple 토크나이저), 본문은 `bm25_text @@@ …`(whitespace). 필요하면 토크나이저 조정 마이그레이션.
- `EMBED_DIM`을 바꾸면 새 마이그레이션으로 `chunks.embedding` 컬럼·HNSW 색인을 다시 만들어야 함.
