## 3. 결정 사항과 이유

- openai SDK는 `>=2.50,<3`로 고정. 3.x는 httpx 대신 `httpx2`를 써서 재정렬(httpx)과 HTTP 스택이 갈리고 명세의 "httpx 목"으로 검증할 수 없음. 2.x(2.54.0)는 httpx 사용 → 테스트는 `httpx.MockTransport`를 `AsyncOpenAI(http_client=...)`에 넣어 검증.
- 구조: `errors.py`(예외·상태코드 변환), `nvidia.py`(`RetryPolicy`, `_Caller` 재시도+로그, LLM·임베딩·재정렬, `ThinkingFilter`), `factory.py`(`create_llm_provider`/`create_embedding_provider`/`create_rerank_provider`, 재정렬은 `RERANK_ENABLED=false`면 None).
- 재시도: openai SDK `max_retries=0`, tenacity `stop_after_attempt(5)`, `wait_exponential(multiplier=2, max=60)+wait_random(0,1)`. 테스트는 `RetryPolicy(initial_wait=0)`. 재시도 대상은 RateLimited·ProviderUnavailable(5xx·타임아웃·연결 실패). 예외에 `attempts` 속성.
- 스트리밍 LLM은 스트림을 여는 데까지만 재시도(토큰을 내보낸 뒤에는 재시도 불가).
- 추론 제거: `reasoning_content`는 읽지 않음 + 본문 앞 `<think>…</think>`를 상태 기계로 제거(조각 경계 대응). 닫히지 않은 추론은 버림.
- 임베딩 묶음 500: 묶음(2개 이상)의 500은 재시도하지 않고 바로 반으로 나눠 다시 보냄(`provider.embed.split` 로그). 1개짜리 500은 일반 재시도.
- 새 설정: `LLM_TEMPERATURE`=0.2, `LLM_MAX_TOKENS`=2048, `LLM_READ_TIMEOUT`=180, `PROVIDER_READ_TIMEOUT`=60(임베딩·재정렬). `RERANK_URL` 기본값을 check_nvidia.py와 같은 주소로.
- TRD 수정 이유: 구현에 맞춰 openai 2.x 고정(2장), 예외 변환·provider.call(6.2), 임베딩 요청 필드(6.3), 새 설정·RERANK_URL 기본값(12.1). PRD와 충돌 없음.
- E2E는 바꾸지 않음: 사용자 화면 변화가 없고, E2E는 항상 Fake Provider(외부 호출·provider.call 없음).
- 로그 `provider.call`: kind, op, model, latency_ms, status_code, attempts, retries, outcome, (error), items·input_type·first_token_ms. 본문·키 없음. 재시도마다 `provider.retry`.

## 6. 알려진 문제·막힌 점 / 다음 작업에 넘길 것

- 사용법: `create_llm_provider()`, `create_embedding_provider()`, `create_rerank_provider()`(RERANK_ENABLED=false면 None). NVIDIA Provider는 `aclose()`로 HTTP 클라이언트를 닫음 → 앱 수명주기(lifespan)·Worker에서 한 번 만들고 종료 시 닫을 것.
- Worker(embed 작업): `RateLimited`를 받으면 `run_after`를 30분 뒤로 반납(TRD 6.2). `ProviderAuthError`는 재시도 없이 실패 처리, `EmbeddingDimensionError`는 설정 문제로 멈춤.
- T16(/health): `provider.call` 로그나 Provider 쪽 훅으로 마지막 성공·실패 시각과 오류 코드를 기록해야 함(지금은 로그만 남김).
- 스트리밍 중간(토큰을 보낸 뒤) 오류는 재시도하지 않고 Provider 예외로 그대로 올라감 → 질의 그래프가 SSE `error`로 바꿀 것.
- `<think>` 제거는 답변 맨 앞의 태그만 처리. 여는 태그 없이 `</think>`만 오는 모델은 처리하지 않음(현재 모델은 reasoning_content로 분리됨).
