## 3. 결정 사항과 이유

- 코드 위치: `backend/app/sync/`(runs.py 실행 기록·abandon, manifest.py 판정, documents.py 이동·복사, upload.py 업로드 수신), 라우터 `backend/app/api/sync.py`(라우터 의존성 `require_sync_token`).
- multipart를 위해 `python-multipart` 의존성 추가.
- 업로드 경로 검증 = `check_scope(path, SYNC_ALLOWED_ROOT, excludes)` + `sync_config.roots` 중 하나의 하위 + 확장자 화이트리스트. 오류는 400, code는 이유 그대로(`outside_root`, `fixed_exclude`, `excluded`, `relative_path`, `unsupported_extension`). 크기 초과 413 `file_too_large`.
- 삭제 판정 대상: `locally_deleted=false`이고 범위 안(허용 폴더·roots·제외 패턴)인 문서 중 manifest에 없는 것. 범위 밖 문서는 설정 저장 시 영구 삭제 대상이라 건드리지 않음.
- 대량 삭제 보호 비율 = 새 삭제 판정 수 / 범위 안 활성 문서 수(이번 판정 전). `>` 비율이면 모두 보류.
- 복사는 원본이 추출을 끝낸 경우(content_indexed, needs_upload 아님, queued·extracting 아님)만. 아니면 upload로 처리.
- [시도 2, 채점 블로커 수정] 원본이 임베딩 끝난 경우만 복사본 `embed_charged_sha256 = sha256`(API·한도 사용 없음). 원본이 indexed/embedding이면 복사본은 indexed + 일반 embed 작업 + `embed_charged_sha256=None` → claim_embed가 하루 파일 한도를 확인·차감(한도 찬 날은 가져가지 않음). 이유: '이미 차감' 표시로 두면 한도가 찬 뒤에도 API를 불러 하루 한도를 넘김. 원본 embed 완료 시 벡터 전파 방식은 원본 실패·수정 시 복사본이 멈출 위험이 있어 택하지 않음.
- [시도 2] 이동·복사 원본은 같은 확장자만(`d.ext == meta.ext`). 이동 원본에서 옛 경로가 scan_errors 아래인 문서는 제외(복사 또는 업로드).
- [시도 2] SyncScope/load_scope를 `app/sync/scope.py`로 분리. 파일명 청크 판별 `_is_filename_chunk`/`_apply_filename_chunk`로 통합. api/sync.py 타입(`SyncRun`, `Awaitable[SyncRun]`).
- [시도 2] 업로드 Form·메타 body에 선택 `run_id`(로그 상관 키). 업로드 관련 로그에 `run_id`, `sha256_prefix`(해시 앞 8자리).
- [시도 2] Worker `build_scheduler()` 분리(작업 ID `abandon_stale_sync_runs` 등) → 테스트가 등록·간격 확인. 같은 연결 세션 팩토리(`async_sessionmaker(bind=session.bind, join_transaction_mode="create_savepoint")`)로 Worker·JobRunner를 롤백 트랜잭션 안에서 테스트.
- 이동: path·path_key·filename·ext 갱신, 청크 filename 갱신, 파일명 청크(내용이 옛 filename_chunk와 같은 청크)는 새로 만듦. content_sha256은 유지(저장된 임베딩의 실제 입력 해시).
- manifest가 문서를 만들지 않음. upload 판정 문서는 업로드 때 생김(업로드 실패 시 다음 manifest에서 다시 upload).
- 응답에 명세 7개 목록 외에 `scan_error_held`, `rejected`, `counts` 추가. scan_errors 보류는 `deletion_held`(대량 삭제 보호 전용, TRD 8.2)와 분리.
- stats: `manifest`(건수), `deletion_held`(`mass_delete`{count,total,ratio,threshold,sample}, `scan_error`{count,sample}). complete의 Agent stats는 이 두 키를 덮지 못함.
- 하트비트가 abandoned 실행에 오면 running으로 되돌림(`sync.run.resumed`). 끝난 실행에 요청 → 409 `run_finished`, 없는 실행 404 `run_not_found`.
- stale run 처리: `Worker.abandon_stale_sync_runs`를 APScheduler 1분 간격 + 시작 시 1회. 함수는 `app.sync.runs.abandon_stale_runs(session, now=, stale_after=)`.
- E2E(`web/e2e/sync.spec.ts`): 화면이 없어 Playwright `request`로 Agent 요청을 직접 보냄. 토큰은 CLI `create-token` 출력 마지막 줄. 경로는 `C:\Chanjin\dev\e2e-sync-<stamp>\…` 문자열(백엔드 SYNC_ALLOWED_ROOT 기본값). 업로드된 extract 작업은 빈 폴더로 `ingest-local`을 돌려 처리(같은 UPLOAD_TMP_DIR)해서 큐를 비움 → ingest.spec과 간섭 없음. 이전 실행 문서가 남아도 manifest에 없는 문서가 많아 항상 대량 삭제 보호에 걸리므로 결과가 결정적.
