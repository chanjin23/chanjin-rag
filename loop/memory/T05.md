## 3. 결정 사항과 이유

- Kiwi 결과 확인: "위약금조항" → 위약금 NNG + 조항 NNG(붙어 있음). 복합명사 = 띄어쓰기 없이 붙은 NNG/NNP 연속
  (start==이전 end). 태그는 `VA-I`처럼 접미가 붙으므로 `-` 앞만 본다. XSN(-들 등)은 합치지 않음.
- Kiwi 기본 Match는 URL·이메일·날짜(W_SERIAL)를 한 토큰(W_*)으로 묶어 TRD 품사 목록에 걸려 버려짐 →
  URL·EMAIL·SERIAL·HASHTAG·MENTION 매칭을 꺼서 SL·SN 조각으로 남긴다(TRD 품사 목록 그대로 유지). TRD 6.4에 적음.
- "했다"처럼 단독 동사 "하"(VV)는 TRD대로 남는다(노이즈지만 문서·질문 같은 함수라 일관).
- 토크나이저: `KiwiTokenizer(user_dict)` 클래스 + `get_tokenizer()`(사전 경로별 lru_cache) + `bm25_tokens`/`bm25_text`.
  사전 경로는 설정 `KIWI_USER_DICT_PATH`(빈 값이면 `REPO_ROOT/deploy/kiwi_user_dict.txt`), 파일 없으면 사전 없이.
- 토큰 수: tiktoken o200k_base, `disallowed_special=()`. `token_count`와 500~800 범위는 `content` 기준(머리말 제외).
  인코딩 파일은 첫 사용 때 인터넷에서 받아 캐시(오프라인 이미지면 TIKTOKEN_CACHE_DIR 미리 채우기, TRD 6.3에 적음).
- 묶음 키: slide=항상 단독, table=(heading_path, location에서 row/rows 뺀 값), text=heading_path. 연속 섹션만.
- 채우기: 순서대로 800까지(정확히 재인코딩해서 확인). 다음 문단이 안 들어가면 그대로 끊음 → 500 미만 청크 가능(TRD에 명시).
  800 초과 문단만 문장(`.!?。` 뒤 공백 또는 줄바꿈)→단어→토큰(decode_with_offsets) 순으로 자름.
- 겹침: 앞 청크 content 끝에서 토큰 10~15% 구간 안의 시작점, 문장 시작 우선→단어 경계→토큰 꼬리. 겹침+새 단위가
  800을 넘으면 겹침 생략. 겹침 부분은 location에 넣지 않음. 표는 겹침 없음.
- 표 헤더 반복: 파서가 행마다 `헤더: 값 | …`이므로 별도 헤더 줄을 넣지 않음(토큰 절약). 표 한도 600, 한 행이 800 초과일 때만 자름.
- 파일명 청크: content=`파일명
경로`(경로 없거나 같으면 파일명만), location {}, heading_path [], kind="meta", embeddable=False.
- bm25_text는 content만 토큰화(파일명·제목은 BM25 색인의 filename·heading_path 컬럼이 담당).
- 순수 함수라 로그 이벤트는 넣지 않음(T06 index 작업에서 청크 수 등을 로그로 남길 것). 사용자 화면 변화 없어 E2E 변경 없음.
- 샘플 205개 문서 실측: 청크 1812개(text 1736, slide 29, table 47), 800 초과 0, 500 미만 약 90%
  (원인은 제목 구간 자체가 짧음 — 같은 묶음 중간의 작은 청크는 3개뿐). 청킹 3.7초.

## 6. 알려진 문제·막힌 점 / 다음 작업에 넘길 것

- T06: `from app.ingest.chunking import build_chunks, filename_chunk` →
  `build_chunks(result.sections, filename=, path=, meta_only=)`가 `Chunk`(seq, kind, location, heading_path, content,
  embed_text, content_sha256, bm25_text, token_count, embeddable) 목록을 돌려줌. DB `chunks`에 그대로 매핑
  (filename 컬럼은 documents.filename). `embeddable=False`면 embed 작업 대상에서 뺄 것.
  `unsupported_format`·`no_text`는 `filename_chunk(filename, path)`. index 작업에서 청크 수·토큰 합 로그 이벤트를 남길 것.
- 질의(retrieve): `from app.ingest.tokenize import bm25_text`로 질문 토큰화(같은 함수). 다른 토큰화 경로 만들지 말 것.
- 배포 이미지: tiktoken o200k_base 파일을 빌드 때 받아 두기(TIKTOKEN_CACHE_DIR), kiwipiepy 모델 포함 확인,
  `deploy/kiwi_user_dict.txt`를 이미지/볼륨에 두고 KIWI_USER_DICT_PATH 지정.
- 평가(eval): 500토큰 미만 청크가 많음(짧은 제목 구간). 형제 제목 구간을 합칠지 평가셋으로 판단할 후보.
  `하`(VV) 같은 흔한 어간 토큰을 불용어로 뺄지도 후보.
