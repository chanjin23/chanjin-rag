## 3. 결정 사항과 이유

- 설계(세션 1):
  - 임시 원본 위치: `UPLOAD_TMP_DIR`(기본 `REPO_ROOT/var/tmp`) 아래 `{document_id}-{sha256}{ext}`. 새 컬럼 없이 작업에서 경로를 계산.
  - 시계 주입: `JobRunner(clock=…)`, SQL 비교도 Python 시각 파라미터 사용(테스트에서 자정·30분 뒤를 흉내).
  - 모든 작업은 가져갈 때(claim) 문서 sha와 비교해 다르면 바로 폐기(embed는 한도 차감 전에 폐기).
  - 한도 소진 시: 이미 차감된 버전(429로 반납된 것)만 계속 가져갈 수 있고, 없으면 `QuotaExhausted(resume_at=다음 KST 자정)`.
  - 청크 상한은 차감 여부와 상관없이 새 embed 작업을 막음(진행 중인 작업은 끝까지).
  - "32개 배치" = embed 작업이 청크를 32개씩 묶어 저장(트랜잭션마다 stale 검사, locked_at 갱신). API 요청 크기는 `EMBED_BATCH_SIZE`(무료=1), 동시 2개.
  - extract에서 no_text·unsupported_format은 바로 파일명 청크를 만들고 끝(index 작업 없음).
  - 그 밖의 파싱 실패(corrupted 등)는 sections만 지우고 이전 버전 chunks는 건드리지 않음(TRD에 규정 없음).
  - extract 중 예외 → 원본은 이미 지움 → 재시도 때 "임시 원본 없음"으로 failed(parser_error) + needs_upload=true.
  - 오류 재시도: RateLimited·ProviderAuthError·EmbeddingDimensionError는 30분(`JOB_RATE_LIMIT_DELAY_MINUTES`),
    그 밖은 1·2·4…분(최대 30). attempts는 claim 때 +1, `attempts >= JOB_MAX_ATTEMPTS`(5)면 failed.
    embed 반납 시 문서 `indexed`, 최종 실패 시 문서 `failed`(failure_code 없음, detail에 오류).
  - 지난 버전 extract 작업을 버릴 때 그 버전의 임시 원본도 지움. 접수 시 같은 문서의 다른 버전 원본도 지움(Windows 열린 파일은 무시).
  - runner가 등록하는 index/embed 작업의 run_after는 runner 시계(테스트 시계와 맞추기 위함).
  - structlog `cache_logger_on_first_use=False`로 바꿈: 모듈 전역 로거가 CLI 실행 때 설정에 캐시되어
    이후 테스트의 capture_logs가 안 잡히는 문제. 로거 출력은 `_CurrentStdout`(그때의 sys.stdout).
  - Worker 하트비트는 새 테이블 `worker_heartbeats(name PK, started_at, heartbeat_at, pid, info)`.

## 6. 알려진 문제·막힌 점 / 다음 작업에 넘길 것

- T07(Sync API): 업로드는 `app.ingest.intake.accept_upload(session, FileMeta(path,size,mtime,sha256), 임시파일, move=True)`,
  10MB 초과는 `accept_meta_only`. 범위 검증은 `app.ingest.scope.check_scope(path, SYNC_ALLOWED_ROOT, excludes)`
  (`FIXED_EXCLUDES`, `UPLOAD_EXTENSIONS`, `is_upload_extension`). commit은 호출한 쪽. 이동·복사 판정과 hash_mismatch는 T07.
- `ingest-local`은 E2E 시드에 쓸 수 있음(`web/e2e/ingest.spec.ts`의 `ingestLocal` 참고: SYNC_ALLOWED_ROOT·UPLOAD_TMP_DIR·LOG_FILE env).
- T16(/health): `worker_heartbeats.heartbeat_at`(이름 `worker`)을 읽으면 됨. `rag-backend worker`가 30초마다 갱신.
- 파서 경고(`scanned_page` 등)는 아직 DB에 저장하지 않고 로그(`job.completed`의 warnings 수, parse.completed)만 남김 → 문서 화면(T08)에서 필요하면 컬럼 추가.
- 영구 삭제(6.5)는 `intake.remove_originals(document_id)`로 임시 원본도 지울 것.
- embed 최종 실패 문서는 status `failed` + failure_code 없음(detail만). 재처리 화면에서 구분 필요하면 코드 추가 검토.
- structlog 로거 캐시를 껐음(`cache_logger_on_first_use=False`) — 로그 테스트가 설정 재구성 뒤에도 잡히게.
