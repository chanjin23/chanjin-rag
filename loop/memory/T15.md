## 3. 결정 사항과 이유

- 질의 임베딩은 원래 한도(embed_quota)를 쓰지 않음(검색 경로에 quota 없음) → 평가도 그대로, config에 `embed_quota: "not_counted"` 기록.
- query_logs에 `source` 열 추가(마이그레이션 0005, 'chat'|'eval', 기본 'chat'). QueryTrace.source / log_id 추가.
- eval 순위: trace.retrieved의 마지막 attempt를 (rerank 내림차순, rank) 정렬 → chunk의 경로·위치를 DB에서 조회.
- 위치 겹침: 라벨 위치가 {}면 경로만 같으면 일치. 아니면 공통 키가 1개 이상이고 공통 키 범위가 모두 겹쳐야 일치(`key`~`key_end`, `lines`는 [a,b]).
- 경로 비교: make_path_key(경로의 '/'→'\\').
- eval/tests conftest는 backend/tests/conftest.py를 importlib로 읽어 픽스처를 다시 내보냄(+ backend/tests를 sys.path에, chat_seed 재사용).
- E2E: 합성 MD를 ingest-local → `uv run rag-eval run --dataset`(저장소 루트, LOG_FILE=백엔드 로그)을 두 번. 두 번째 평가셋에 위치 안 맞는 라벨(lines 900~910) 문항 → Recall 1.000→0.500, 경로 없는 문항 → 제외.
- 피드백 검토 API: GET /feedback?rating=-1, PATCH /feedback/{id}(failure_type, reviewed_at=now). rating 쿼리는 int로 받고 직접 검사(Literal 쿼리는 문자열 "-1"을 422로 거절함).
- 판정: EVAL_JUDGE_MODEL(기본 meta/llama-3.3-70b-instruct), NVIDIA_JUDGE_API_KEY. fake면 FakeLLMProvider(model="fake-judge", responder=fake_judge_responder).
- 비교(증감) 함수는 backend `app/api/eval.py`의 `metric_deltas`에 두고 CLI도 이걸 씀(eval 패키지가 backend에 의존).
