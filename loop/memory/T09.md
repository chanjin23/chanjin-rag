## 3. 결정 사항과 이유
- pg_search 0.26.5 실측: `col ||| 'a b'`(match disjunction, 필드 토크나이저로 자르고 OR) + `pdb.score(c.id)`.
  `@@@ '문자열'`은 쿼리 파서라 `:`·괄호·따옴표가 섞인 토큰에서 깨질 수 있어 `|||` 사용.
  bm25_text·filename·heading_path 세 필드를 OR로 검색(점수 합산됨 확인). documents 조인+필터 동작 확인.
- 디렉터리 필터: `LIKE`는 `\`가 이스케이프 문자라 Windows 경로에서 틀림 → `starts_with(d.path_key, :dir)`.
  접두어는 make_path_key + `/`→`\` + 끝에 `\` 붙임(`c:\a`가 `c:\ab\...`에 걸리지 않게).
- 문서당 최대 3개는 SQL 최종 30개 선택에서 적용(ROW_NUMBER PARTITION BY document_id).
- coverage: bm25_docs=청크가 1개라도 있는 문서, vector_docs=임베딩된 청크가 있는 문서,
  pending_docs=status in (queued, extracting, embedding), total_docs 추가(필터 결과 0개 판단용, T10).
- `hnsw.iterative_scan=relaxed_order`, `hnsw.ef_search=100`을 SET LOCAL(트랜잭션 안). 순위는 CTE 안 ROW_NUMBER로 다시 계산.
- 창 함수 위치: TRD 원안처럼 `ROW_NUMBER() OVER (ORDER BY dist)`를 LIMIT과 같은 단계에 두면 필터된 모든 행을
  정렬하게 됨 → 안쪽 `ORDER BY … LIMIT 50` 뒤 바깥에서 ROW_NUMBER. EXPLAIN(3000청크, enable_seqscan=off)으로
  `Index Scan using ix_chunks_embedding_hnsw` + 디렉터리·형식 필터 함께 동작 확인.
- 검색 함수: `hybrid_search(session, query, query_vector=, filters=, keyword_query=, ...)`(벡터 없으면 BM25만),
  `search(session, embedder, query, ...)`(질문 임베딩 후 hybrid_search, ProviderError면 BM25만 + `search.embed_failed`).
  필터 결과 0개(total_docs=0)면 SQL 생략. 로그 `search.completed`(건수·지연·coverage 숫자·필터 이름만, 질문·경로 없음).
- `SET LOCAL paradedb.planner_warnings='Off'`: documents 조인마다 "JoinScan not used" WARNING이 나와서.
- **`documents.ext`는 실제 수집 경로(intake·sync)에서 점 포함(`.md`)으로 저장됨**(TRD는 "소문자"만 적혀 있었음).
  형식 필터는 `ltrim(d.ext, '.') = ANY(:exts)`(입력은 점 없이 소문자로 정규화) → 두 형식 모두 맞음. E2E에서 발견.
- E2E: 화면이 없으므로 T06처럼 CLI(`rag-backend search`)로 실제 DB 검색 + `search.completed` 로그 확인.

## 6. 알려진 문제·막힌 점 / 다음 작업에 넘길 것

- T10(retrieve 노드): `from app.query.search import search, SearchFilters` →
  `await search(session, embedder, rewritten, filters=, keyword_query=)` → `SearchResult(hits, coverage, filters,
  latency_ms, vector_used, keyword_tokens)`. `coverage.total_docs == 0`이면 "필터 조건에 맞는 문서가 없습니다"
  (전체 문서 0개 판단은 필터 없이 `compute_coverage(session)`). 질의 로그: `filters.model_dump(mode="json")`,
  `retrieved=[h.log_entry() for h in hits]`(재정렬 점수는 T10에서 추가), `coverage.as_dict()`, `latency_ms`.
- T10: 재정렬 뒤 최종 8개 선택에서도 문서당 최대 3개를 지킬 것(검색 단계 30개에는 이미 적용됨).
  재정렬·생성에는 `SearchHit.content`(본문 전체), 화면 인용 미리보기에는 `snippet`.
- 웹 필터 UI(TRD 9.1)·API 요청의 `filters`는 `SearchFilters`(pydantic) 그대로 받으면 됨. 날짜만 받으면
  `--to`처럼 그날 끝(23:59:59.999999, KST)으로 바꿀 것(cli.py `_parse_when` 참고).
- `chunks.embed_model`이 현재 임베딩 모델과 다른 청크(모델 교체)는 걸러내지 않음 → 모델 교체 작업에서 처리.
