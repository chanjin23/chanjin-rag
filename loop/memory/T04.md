## 3. 결정 사항과 이유

- pymupdf는 `<2`로 고정: 2.x는 onnxruntime·numpy·pymupdf4llm 등을 끌어와 이미지가 무거워짐. 쓰는 API는 1.x에 다 있음.
  mypy strict에서 untyped call이라 `_fitz: Any = pymupdf`로 다룸.
- 섹션 단위: PDF=페이지(`{"page": n}`), DOCX=문단 1개(`{"paragraph": n}`, 제목은 heading_path로만),
  DOCX 표=행 1개(`{"table": t, "row": r}`, `헤더: 값 | 헤더: 값`, kind=table, 빈 값 생략, 헤더 빈 열은 `열n`),
  PPTX=슬라이드 1개(`{"slide": n}`, kind=slide, 제목→본문(위→아래·왼→오)→표→`발표자 노트:` 줄+노트),
  TXT·MD=빈 줄로 나눈 문단(`{"lines": [s, e]}`). 섹션을 잘게 둬야 T05 청크 위치가 정확함.
- DOCX 제목: 문단/스타일의 outlineLvl → 스타일 이름 `Heading n`/`제목 n`(기반 스타일 따라감), `Title`=0수준.
- TXT 인코딩: BOM→UTF-8 strict→charset-normalizer, EUC-KR 계열 판별이면 cp949로 디코드. NUL 바이트면 corrupted.
- 실패 코드 매핑: 열기 실패(ZIP 아님, ValueError 내용 형식 불일치, KeyError, XML 오류)=corrupted,
  PDF needs_pass=encrypted, OLE 파일 안 `EncryptedPackage`=encrypted(Office 암호), MemoryError=memory,
  그 밖의 예외=parser_error(메시지에서 경로 지움, 500자). 섹션 텍스트 0자면 `no_text`.
- `unsupported_format`: `.hwp .hwpx .xlsx`와 등록 안 된 확장자. 하위 프로세스를 띄우지 않음.
  DB에 저장되므로 `FailureCode`에 추가하고 CHECK 제약을 바꾸는 마이그레이션 0002 추가
  (test_migrations의 head 리비전 기대값 "0001"→"0002"로 갱신. 약화 아님).
- 격리: `subprocess`로 `python -m app.ingest.parsers._child` 실행, 결과는 stdout에 `@@PARSE_RESULT@@`+JSON
  (자식은 fd1을 stderr로 돌리고 복제 fd에만 결과를 씀). multiprocessing spawn은 pytest.exe 등 __main__
  재import 문제가 있어 피함. 패키지 `__init__`은 isolation(설정·structlog)을 import하지 않아 자식 시작이 0.13초.
- 메모리 상한: 자식이 스스로 건다. Windows=Job Object `JOB_OBJECT_LIMIT_PROCESS_MEMORY`(ctypes, Win8+ 중첩 Job 가능),
  POSIX=`RLIMIT_AS`. 넘으면 MemoryError→`memory`. 결과 없이 죽으면 stderr에 MemoryError나 SIGKILL이면 memory,
  아니면 parser_error. 걸지 못하면 `parse.memory_limit_unavailable` 경고 로그(타임아웃은 동작).
  Windows에서 실제로 동작 확인(test_parser_memory_limit_in_subprocess, 512MB 상한에 4GB 할당 → memory).
- 새 설정: `PARSER_TIMEOUT_SECONDS`=60, `PARSER_MEMORY_LIMIT_MB`=1024(0=없음).
- 로그: `parse.completed`(ext, status, sections, chars, warnings, scanned_pages, elapsed_ms, isolated, +호출자 필드),
  `parse.failed`(failure_code 포함). 경로·파일명·본문 없음. 사용자 화면 변화가 없어 E2E는 바꾸지 않음.
- 샘플 테스트: `~$` 임시 파일, 10MB 초과 제외. 모두 하위 프로세스로 파싱. 개수·비율만 출력.
  MD·TXT는 성공률 100%를 요구, DOCX·PPTX는 1개 이상 + 섹션 나온 문서 1개 이상.
