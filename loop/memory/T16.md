- Provider 상태는 프로세스가 둘(API, Worker)이라 DB 테이블 provider_status(kind PK)에 기록. 래퍼(monitor.py)가 호출 결과를 기록, sessionmaker가 설정된 프로세스만 기록(pytest 기본 no-op). 성공은 60초에 한 번만 씀.
- 인증 오류 상태 = last_failure_at > last_success_at 이고 코드가 provider_auth.
- /health는 공개 유지(Playwright·compose 준비 확인용), 항상 200.
- health.degraded는 이슈 서명(코드+since)이 바뀔 때만 기록(폴링 소음 방지), 정상 복귀 시 health.recovered.
- /health 응답의 status는 항상 "ok"(프로세스 생존), 이상은 degraded·issues → 기존 test_chat::test_health·smoke.spec은 equality 대신 status=="ok"+새 필드 검사로 강화.
- worker_missing(하트비트 행 없음)도 배너로 보여줌(운영에서 Worker 미실행은 문제). E2E는 Worker를 안 띄우므로 E2E 화면에 항상 이 배너가 있음(다른 E2E와 충돌 없음: role=alert, role=status 안 씀).
- 배너 닫기: sessionStorage에 `code|since` 키 저장. 이상이 사라지면 키 삭제 → 다시 생기면 다시 표시. since가 바뀌어도 다시 표시.
- E2E 체크리스트: DELETE FROM documents로 실제 0개 상태를 만듦(다른 spec은 자기 문서를 새로 만듦). 문서 0개면 그래프가 모델을 안 부르므로 배너 테스트는 ingest-local로 문서를 넣은 뒤 오류 질문.
- Agent 첫 접속 = api_tokens.first_used_at(resolve_api_token에서 처음 한 번 기록, 마이그레이션은 last_used_at으로 채움).

- /health 공개 요약은 코드만, 세부는 /health/details(세션)로 나눔(시도 2).
- NVIDIA의 크레딧 소진 응답 형식은 실측하지 않음: 402만 ProviderQuotaExhausted로 매핑. 429 본문으로 오는 경우가 확인되면 errors.py에 추가할 것.

- 웹 Health·SetupStatus 타입은 손으로 작성(기존 api/*.ts도 모두 손 작성, openapi-typescript 생성 파이프라인은 아직 없음) — 생성 도입은 후속.
- Provider 상태 기록은 채팅·Worker·ingest-local만. rag-eval CLI·rag-backend search는 기록하지 않음(평가·디버그용).
- E2E는 Worker를 띄우지 않아 화면에 항상 "Worker 실행 안 됨" 배너가 보임(의도된 동작).
