## 3. 결정 사항과 이유

- 백엔드 위치: `app/api/conversations.py`(대화 CRUD + `create_conversation`/`make_title`, chat.py가 가져다 씀),
  `app/api/feedback.py`, `app/api/index.py`(coverage).
- E2E 오류 재현: Fake LLM 응답기에 표식(`[[fake-error-once:<code>]]`)을 두어 같은 질문에 처음 한 번만
  ProviderUnavailable 등을 던진다(PROVIDER=fake에서만 동작). 다시 시도하면 성공.
- `POST /conversations`는 빈 제목("")으로 만들고, 첫 질문이 제목을 채운다. 웹은 빈 제목을 "새 대화"로 표시.
- `GET /conversations/{id}` 메시지에 `feedback`, `not_found`, `coverage`(질의 로그에서) 포함 → 다시 열어도
  찾지 못함 검색 범위·피드백 표시 가능.
- 삭제 로그 `conversation.deleted`에 지운 메시지·질의 로그·피드백 수. 제목·메모 원문은 로그에 남기지 않음.
- 피드백 덮어쓰기는 INSERT … ON CONFLICT(message_id) DO UPDATE. `failure_type`은 유지. 사용자 메시지는 404.
- 웹: 새 대화가 만들어지면 응답 헤더(X-Conversation-Id)로 바로 `/c/{id}`로 replace 이동. 화면 유지를 위해
  ChatPage의 key를 `location.state.createdFrom`(새 대화 화면 key = `new-${location.key}`)로 고정.
- 웹: 마크다운 인용 칩은 remark 플러그인이 text 노드만 바꿈(code/inlineCode는 다른 노드라 그대로). hName `cite` →
  components.cite가 버튼(aria-label `인용 n`). 이미지 → `[이미지: alt]`, 링크 → `글자 (주소)` span, skipHtml.
- 웹: 대화 목록은 `<section aria-label="대화 목록">`(nav로 하면 smoke.spec의 getByRole("navigation")이 2개가 됨).
- `/index/coverage`: compute_coverage(검색과 같은 기준) + by_status + embed_waiting(queued·extracting·indexed·
  embedding) + 완료 예상일(오늘 남은 한도 먼저, 나머지 ÷ 하루 한도). 로그 `index.coverage.read`.
