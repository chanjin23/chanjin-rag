## 3. 결정 사항과 이유

- uuid-utils 0.19.0 DLL을 Windows 애플리케이션 제어 정책이 차단 → 루트 pyproject `[tool.uv] constraint-dependencies = ["uuid-utils<0.19"]`(0.18.0 사용).
- 구조(계획): `app/query/` 아래 `prompts.py`(작업 표식 포함 프롬프트), `postprocess.py`(인용·추론 필터, 스트리밍 대응),
  `summary_target.py`(요약 대상 판정), `graph.py`(StateGraph + context_schema=QueryDeps, `get_stream_writer`로 custom 이벤트),
  `fake_llm.py`(PROVIDER=fake일 때 그래프 프롬프트에 결정적으로 답하는 응답기), `chat_service`는 `app/api/chat.py`에.
- LangGraph 스트리밍은 custom 모드만 사용(LangChain 채팅 모델을 안 쓰므로 messages 모드 불가) → TRD 7.3 문구 수정.
- 대화: 경로 `conversation_id`가 `new`면 대화를 만든다(제목=질문 앞 40자). `done`에 `conversation_id` 추가. 숫자 아닌 값·없는 대화는 404.
  웹은 첫 응답의 conversation_id를 기억해 다음 질문에 씀(대화 목록·URL 이동은 T11).
- 범위 확인(scope) 노드를 그래프 맨 앞에 둠: 필터 결과 0개/문서 0개면 status 없이 token → done(TRD 7.3 순서표).
- 요약 대상 우선순위: `summarize_document_id`(명시적 선택) > 질문의 파일명 > 직전 답변 출처.
- E2E 단계 표시가 보이도록 `FAKE_LLM_TOKEN_DELAY_MS` 설정(E2E만 150ms).
- SSE: 그래프는 별도 task에서 돌리고 큐로 이벤트 전달. 제너레이터 finally에서 끝나지 않았으면(연결 끊김) task 취소 →
  anyio shield 안에서 rollback 후 aborted 저장. 요청 DB 세션은 FastAPI(0.162)가 응답 스트림 뒤에 닫으므로 스트림에서 그대로 사용.
- 테스트: httpx ASGITransport는 응답을 모아서 주므로 순서 검사에 쓰고, 끊김은 ASGI 앱을 직접 불러 http.disconnect 전송.
- Fake 재정렬은 `\w+` 토큰이라 한국어 조사 때문에 순서가 바뀔 수 있음 → 테스트는 "인용 번호의 출처 문서"로 확인.
- `sources`의 참고 후보·요약 후보는 `n: null`, 요약 출처는 `chunk_id: null`. `done`에 `conversation_id` 추가.
- grade JSON 파싱 실패 → "충분"으로 간주(생성 단계 지시가 근거 밖 답을 막음). rewrite/retry 파싱 실패 → 원래 질의.
