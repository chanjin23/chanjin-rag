## 3. 결정 사항과 이유

- 코드 위치: `app/core/security.py`(해시·난수), `app/core/auth.py`(로그인·세션·토큰 서비스), `app/api/deps.py`(FastAPI 의존성), `app/api/auth.py`(라우터), `app/api/errors.py`(`{"error":{code,message}}` 예외).
- 슬라이딩 갱신 쿠키: 엔드포인트가 Response(SSE 등)를 직접 돌려주면 FastAPI가 의존성의 Response 헤더를 합치지 않음 → 의존성이 `request.state`에 표시하고 main.py 미들웨어가 Set-Cookie를 붙임.
- E2E 백엔드(uvicorn, --reload 없음)는 Windows Proactor 루프라 psycopg async 불가 → `--loop asyncio:SelectorEventLoop`(uvicorn 0.54는 사용자 루프 팩토리 import 문자열 허용).
- CSRF Origin 검사: Origin의 host:port가 요청 Host와 같거나 `CSRF_TRUSTED_ORIGINS`에 있어야 함. Vite 프록시 `changeOrigin`을 false로 바꿔 Host를 보존.

- 응답: 로그인 실패 401 `invalid_credentials`, 잠금 429 `login_locked` + `retry_after_s` + Retry-After. 잠금되는 5번째 실패는 `auth.login.failed`와 `auth.login.locked`를 둘 다 남김.
- 라우터: `api_router` 아래 `web_router`(dependencies=WEB_API_DEPENDENCIES)에 웹 API를 붙인다. `/auth/login|logout`은 CSRF만, `/auth/me`는 세션.
- CLI는 명령마다 엔진을 만들고 닫음(`_run_db`), Windows는 `asyncio.run(loop_factory=SelectorEventLoop)`. 비밀번호는 프롬프트 또는 `--password-stdin`(Windows getpass는 stdin을 안 읽어서 E2E용).
- API 테스트: TestClient는 다른 루프라 async 테스트 세션 공유 불가 → `httpx.AsyncClient(ASGITransport)` + `get_session` 오버라이드, base_url `https://testserver`(Secure 쿠키 전송).
- CLI 테스트는 CliRunner 임시 stdout으로 structlog가 재설정됨 → 픽스처에서 `structlog.get_config()` 저장·복원. CLI 로거는 모듈 전역이 아니라 호출 때마다 get_logger(캐시된 닫힌 스트림 방지).
- 웹: `RequireAuth`(GET /auth/me, 401이면 `/login?next=`), `LoginPage`(잠금 카운트다운, reset-password 안내), 채팅 401 → `saveDraft`(sessionStorage `chat-draft:<대화ID>`) 후 `/login?next=..&reason=expired`. 로그인 성공 시 me 쿼리 캐시 채우고 next로 이동. ChatView는 대화ID별 key로 다시 마운트해 보존본을 읽음.
- E2E 세션 만료 흉내: `context.addCookies`로 `sid`를 서버가 모르는 값으로 바꿈(서버 입장에서 만료와 같음). 로그 확인은 `backendLogMark()` 이후 줄만(`waitForBackendLog(match, { since })`).
- auth.spec.ts는 describe 없이 최상위 test(필수 제목과 전체 제목이 같게).
- TRD 고침: 5.2·9.1의 CLI 이름 `backend …` → 실제 스크립트 이름 `rag-backend …`, 8.1에 401/429/403 코드와 SESSION_COOKIE_SECURE·CSRF_TRUSTED_ORIGINS 설명 추가(구현과 맞춤).
- E2E: 사용자 `e2e`를 global-setup에서 reset-password(없으면 create-user)로 준비, setup 프로젝트가 로그인해 storageState 저장. 잠금 테스트는 auth.spec 맨 끝(잠겨도 기존 세션은 유효).

## 6. 알려진 문제·막힌 점 / 다음 작업에 넘길 것

- 새 웹 API는 `app/api/router.py`의 `web_router`에 붙이면 세션 필수 + CSRF가 자동 적용된다. 엔드포인트에서 사용자가 필요하면 `WebUser` 의존성.
- Sync API(T03 이후): 라우터에 `Depends(require_sync_token)` 또는 엔드포인트 인자 `token: SyncToken`. CSRF 검사는 하지 않는다(Bearer).
- 웹: 새 화면의 API 호출은 `apiFetch`(오류는 `ApiError{status, code, detail}`), 401이면 `isUnauthenticated(err)`로 판별해 로그인 화면으로(`loginPath(next, "expired")`). 네트워크 오류 시 입력 보존(TRD 9.2)은 아직 401만 처리.
- E2E 사용자는 단일 계정이라 E2E 중 잠금 테스트 뒤에는 새 로그인이 15분 막힌다. 새 로그인 테스트는 auth.spec.ts의 잠금 테스트보다 앞에 두거나 storageState를 쓸 것.
- 토큰 폐기 CLI(`revoke-token`)·토큰 관리 화면은 범위 밖(필요하면 후속 작업).
