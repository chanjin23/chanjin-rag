# T17 · 배포 구성: Compose, Nginx, 이미지

## 목표

`docker compose up` 한 번으로 db, migrate, api, worker, web이 뜨는 운영 구성을 만든다. arm64 실제 검증은 수동 체크리스트로 넘기고, 여기서는 구성 검증과 로컬 빌드·기동까지 확인한다.

## 근거

- PRD 7장(운영), TRD 3.1~3.3(배포, 컨테이너, 네트워크), 11장(CSP, 업로드 상한), 12.3(배포), 12.5(리소스 예산)

## 구현 항목

- [ ] `deploy/compose.yaml`: db(ParadeDB, 4GB), migrate(1회, 성공 후 api·worker 시작), api(1.5GB), worker(3GB), web(Nginx, 128MB, `127.0.0.1:8080`만), 볼륨 `pgdata`·`tmp`·`backups`, `TZ=Asia/Seoul`, `.env` 사용
- [ ] `backend/Dockerfile`(api·worker 공용, PostgreSQL 17 클라이언트·age 포함), `web/Dockerfile`(빌드 후 Nginx), 모두 arm64 빌드 가능한 베이스 이미지
- [ ] `deploy/nginx.conf`: 정적 파일, `/api` 프록시, SSE 경로 `proxy_buffering off`, `client_max_body_size 12m`, CSP(`default-src 'self'; img-src 'self' data:; connect-src 'self'; frame-ancestors 'none'`)
- [ ] `deploy/postgres/` 조정값(TRD 12.5)
- [ ] `deploy/scripts/deploy.sh`(git pull → build → up -d)
- [ ] `.env.example` 갱신(TRD 12.1 전체)
- [ ] 구성 검증 테스트와 로컬 빌드 확인(추가 검사 명령). 추가 검사는 `.env` 없이도 통과해야 함(`env_file`의 `required: false` 등)
