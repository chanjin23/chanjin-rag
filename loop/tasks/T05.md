# T05 · 구조 기반 청킹과 Kiwi 토큰화

## 목표

`Section` 목록을 TRD 규칙대로 청크로 나누고, BM25용 토큰 문자열을 만드는 단일 토큰화 함수를 둔다.

## 근거

- PRD 5.1-5, 5.1-6, TRD 6.3(청킹 규칙, 머리말, 표, PPTX, meta\_only·no\_text), 6.4(한국어 BM25 토큰화), 2장(tiktoken o200k\_base)

## 구현 항목

- [ ] 같은 `heading_path` 안에서 500~800토큰, 앞 청크 끝 10~15% 겹침, 문단 중간 자르기 금지(800토큰 초과 문단만 문장 단위)
- [ ] 임베딩 입력에는 `[파일명 > 제목 > 소제목]` 머리말, 화면용 `content`에는 없음. `content_sha256`은 임베딩 입력 기준
- [ ] 표: `헤더: 값 | 헤더: 값` 행 묶음(최대 약 600토큰), 청크마다 헤더 반복
- [ ] PPTX: 슬라이드 1장 = 청크 1개(800토큰 초과 시 분할), 노트 포함
- [ ] `meta_only`·`no_text`: 파일명·경로만 담은 청크 1개
- [ ] 청크 `location`은 원래 섹션 위치를 유지
- [ ] Kiwi 토큰화: TRD 6.4의 품사만 남김, 영문 소문자, 복합명사 원형+분해형, 사용자 사전(`deploy/kiwi_user_dict.txt`)
- [ ] 문서와 질문이 같은 함수 하나를 씀

## 범위 밖

- DB 저장과 작업 큐(T06)
- XLSX 시트 파싱(T18로 미룸). 표 청킹은 `kind=table` 섹션(DOCX 표, PPTX 표)으로 검증하며, XLSX가 같은 경로를 쓰도록 형식에 의존하지 않게 만든다
