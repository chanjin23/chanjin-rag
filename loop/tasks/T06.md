# T06 · 작업 큐와 Ingestion Worker

## 목표

`jobs` 테이블 기반 큐로 extract → index → embed를 처리하는 Worker를 만든다. 하루 임베딩 한도, 버전별 차감, 청크 임베딩 재사용, 오래된 버전 결과 폐기를 구현한다.

## 근거

- PRD 3장(임베딩 한도), 5.1-6~7, F-06, TRD 5.1(상태도), 6.2(Worker 처리, 하루 임베딩 한도, 재시도), 6.3, 12.5(Worker 동시성)

## 구현 항목

- [ ] 큐: `SELECT … FOR UPDATE SKIP LOCKED`, `locked_at` 10분 초과 작업 재대기, `run_after`
- [ ] `extract`: 임시 원본 파싱(T04 하위 프로세스) → `sections` 저장 → 원본 삭제(실패해도 삭제) → 상태·사유 기록, 텍스트 0자면 `no_text`, `unsupported_format`(HWP·HWPX·XLSX)이면 `failed`로 기록하되 파일명 청크 1개를 만들어 파일명 검색은 되게 함
- [ ] `index`: 청킹·토큰화(T05) → `chunks` 한 트랜잭션 교체 → 같은 문서의 이전 청크와 `content_sha256`·`embed_model`이 같으면 벡터 재사용 → 모두 채워지면 바로 `ready`, 아니면 `embed` 작업 등록
- [ ] `embed`: 우선순위(수정 시각) 순, `embed_charged_sha256`로 버전당 1회 차감, 한도 100(`EMBED_DAILY_FILE_LIMIT`), 하루 청크 상한(`EMBED_DAILY_CHUNK_LIMIT`, 0이면 없음), 한도 도달 시 다음 날 0시(KST)까지 대기, 32개 배치
- [ ] 429 지속 시 `run_after` 30분 뒤 반납(같은 버전은 재차감 없음), 재시도 초과 시 `failed`
- [ ] 결과 저장 시 `jobs.sha256` ≠ 문서 현재 해시면 결과 폐기
- [ ] Worker 프로세스: 작업 루프 + APScheduler(자정 한도는 날짜 키로 자연 초기화, 30초 하트비트 기록), 파싱 동시성 1, 임베딩 호출 동시 2
- [ ] 개발·E2E용 CLI `ingest-local <폴더>`: Agent 없이 로컬 폴더 파일을 업로드 경로와 같은 방식으로 큐에 넣고 처리(E2E 시드 데이터용). 루트 검증은 동일하게 적용하되 테스트용 루트를 설정으로 지정 가능
- [ ] 로그: `job.started`, `job.completed`, `job.failed`, `job.discarded_stale`, `quota.exhausted`
