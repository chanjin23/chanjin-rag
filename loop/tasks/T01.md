# T01 · DB 스키마와 Alembic 마이그레이션

## 목표

TRD 5장의 모든 테이블과 색인을 SQLAlchemy 2.0(async) 모델과 Alembic 마이그레이션으로 만든다.

## 근거

- TRD 5.1~5.4(테이블, 상태도, 색인), 3.2(`migrate` 서비스), 12.3(마이그레이션)

## 구현 항목

- [ ] `app/db/`: 엔진·세션 팩토리(async, psycopg 3), 모델: `sync_config`, `documents`, `sections`, `chunks`, `jobs`, `embed_quota`, `sync_runs`, `users`, `sessions`, `api_tokens`, `conversations`, `messages`, `query_logs`, `feedback`, `eval_runs`, `eval_results`
- [ ] 컬럼은 TRD 5장 그대로(`path_key` NFC+소문자 unique, `embed_charged_sha256`, `content_sha256`, `jobs.sha256`, `sync_runs.heartbeat_at`, `messages.status` 등). 상태 값은 문자열 Enum으로 제한
- [ ] 색인: `chunks.embedding` HNSW(`halfvec_cosine_ops`, `EMBED_DIM` 기준), `chunks.bm25_text` pg\_search BM25(파일명·heading 포함), `documents`·`jobs` 색인
- [ ] `backend/alembic/` 초기 마이그레이션, `upgrade`/`downgrade` 모두 동작
- [ ] `sync_config` 단일 행 초기값(루트 `C:\Chanjin\dev`, 기본 제외 패턴)
- [ ] `rag-backend migrate` 또는 문서화된 명령으로 마이그레이션 실행

## 범위 밖

- 각 테이블을 쓰는 비즈니스 로직(이후 작업)
