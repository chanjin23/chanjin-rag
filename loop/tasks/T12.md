# T12 · 문서 화면: 상태, 상세, 재처리, 영구 삭제

## 목표

문서 처리 상태를 보고, 실패 사유와 해결 안내를 확인하고, 재처리·영구 삭제를 할 수 있는 화면과 API를 만든다.

## 근거

- PRD F-05, F-10, F-19, TRD 3.4(실패 사유 코드 표), 5.1(화면 상태 매핑), 6.5(영구 삭제 범위, 인용 가림), 8.3(`/documents*`), 9.1(`/documents`, `/documents/:id`)

## 구현 항목

- [ ] API: `GET /documents`(상태·형식·경로·검색어·로컬 삭제 필터, 페이지네이션), `GET /documents/{id}`(위치별 추출 텍스트), `POST /documents/{id}/reprocess`(실패는 `needs_upload`, 정상은 sections에서 재청킹), `DELETE /documents/{id}`(영구 삭제), `GET /documents/suggest`(폴더 자동완성)
- [ ] 영구 삭제: documents·sections·chunks·jobs·임시 원본, 사용자 삭제는 `messages.citations` 인용 구절을 "삭제된 문서"로 가림, 확인 창에 백업·외부 전송 안내 문구
- [ ] 화면 탭: 대기, 처리 중, BM25만, 완료, 텍스트 없음, 실패, 파일명만, 로컬 삭제
- [ ] 실패 사유와 해결 안내(TRD 3.4 표 문구)
- [ ] 재처리 후 "다음 동기화 대기" 표시와 "지금 동기화" 이동 버튼
- [ ] 상세: 위치별 추출 텍스트, `?loc=`로 인용 위치 스크롤·강조, "이 문서 요약" 버튼(채팅으로 `summarize_document_id` 전달), 삭제·변경된 문서면 저장된 인용 구절과 안내
- [ ] 채팅의 디렉터리 필터에 `/documents/suggest` 자동완성 연결
- [ ] 로그: `documents.reprocess.requested`, `documents.purged`(원인, 개수만)

## 범위 밖

- 범위 변경에 따른 삭제(T13), 30일 자동 삭제(T14)
