# T07 · Sync API: manifest 판정, 업로드, 실행 기록

## 목표

Sync Agent가 쓰는 서버 API를 만든다. 변경 판정은 서버가 하고, 이동·복사·삭제·복원·보류를 TRD 판정표대로 처리한다.

## 근거

- PRD 3장(수집 범위, 동기화, 서버 데이터 삭제), 5.1-3, F-02, TRD 6.1(판정표, 대량 삭제 보호, Agent 쪽 규칙의 서버 측 검증), 8.2, 11장(업로드)

## 구현 항목

- [ ] `GET /sync/config`: 루트, 제외(고정 제외 포함 표시), `max_file_mb`
- [ ] `POST /sync/runs`, `POST /sync/runs/{id}/heartbeat`, `POST /sync/runs/{id}/complete`(통계 저장)
- [ ] `POST /sync/runs/{id}/manifest`: TRD 6.1 판정표를 위에서부터 순서대로 적용. 응답 목록 `upload`, `meta_only`, `deleted`, `restored`, `moved`, `copied`, `deletion_held`
- [ ] 이동은 경로만 갱신(청크의 경로 관련 값도 갱신), 복사는 sections·chunks·임베딩 복사, 둘 다 한도 미사용
- [ ] `scan_errors` 아래 경로는 삭제 판정 보류, 새 삭제 판정이 전체의 20%(`MASS_DELETE_GUARD_RATIO`) 초과면 모두 보류하고 `stats`에 기록
- [ ] `PUT /sync/files`: 서버 해시 재계산, 다르면 409 `hash_mismatch`, 루트 안·고정 제외 아님·확장자 화이트리스트(대소문자 무시) 검증, `tmp`에 저장 후 `extract` 작업 등록(T06)
- [ ] `POST /sync/files/meta`: 10MB 초과 파일을 `meta_only`로
- [ ] `heartbeat_at`이 10분(`SYNC_RUN_STALE_MINUTES`) 넘게 없는 `running` 실행을 `abandoned`로 바꾸는 예약 작업
- [ ] 로그: `sync.run.started`, `sync.manifest.judged`(건수만), `sync.file.uploaded`, `sync.deletion.held`, `sync.run.completed`
