# T14 · 데이터 수명주기: 30일 삭제, 백업, 백업 내려받기

## 목표

로컬 삭제 문서의 30일 뒤 자동 삭제, 매일 암호화 백업, Agent의 백업 내려받기·보관을 만든다.

## 근거

- PRD 3장(DB 백업, 서버 데이터 삭제), 7장(운영, 개인키 보관), F-19, TRD 6.5, 8.2(`/sync/backups*`), 10.3, 12.2

## 구현 항목

- [ ] 예약 작업(매일 04:00 KST): `deleted_at` 30일(`LOCAL_DELETED_RETENTION_DAYS`) 지난 문서 영구 삭제, 이 경우 인용은 가리지 않음
- [ ] 예약 작업(매일 03:00 KST): `pg_dump -Fc` → `age -r <BACKUP_AGE_RECIPIENT>` → `backups/rag-YYYYMMDD.dump.age`, VM에는 최근 3개(`BACKUP_KEEP_ON_VM`). 외부 명령 실행은 주입 가능한 실행기로 감싸 테스트에서 가짜로 검증
- [ ] `GET /sync/backups/latest`(파일명, 크기, SHA-256), `GET /sync/backups/{name}`(경로 조작 차단)
- [ ] Agent: 동기화 후 없는 백업만 내려받기, SHA-256 검증 실패 시 삭제, 날짜순 7개 초과 삭제, 저장 위치는 설정값(기본 `C:\Chanjin\dev\backup`)
- [ ] `deploy/scripts/backup.sh`, `restore.sh`(TRD 12.2 절차)
- [ ] 로그: `documents.purged`(원인 `retention`), `backup.created`, `backup.failed`, `backup.downloaded`

## 범위 밖

- 실제 VM에서의 복구 훈련(수동 체크리스트)
