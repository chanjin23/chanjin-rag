# T08 · Windows Sync Agent

## 목표

`rag-agent`가 폴더를 스캔해 manifest를 보내고, 판정대로 업로드하며, URL 프로토콜(`run`, `reveal`)을 안전하게 처리한다. 실제 작업 스케줄러·레지스트리 등록은 dry-run으로만 검증한다.

## 근거

- PRD 3장(동기화, 원본 파일 열기), F-02, F-03, TRD 6.1(시퀀스, Agent 쪽 규칙), 10.1~10.2, 11장(Agent 토큰)

## 구현 항목

- [ ] 스캔: 고정 제외 `/project/`, `/backup/`(루트 기준), 기본 제외(gitignore 문법, pathspec), 지원 확장자만(대소문자 무시), 건너뛴 형식 통계, NFC 경로, 루트 밖 심볼릭 링크 미추적
- [ ] 해시 캐시: `%LOCALAPPDATA%\chanjin-rag\state.db`(테스트에서는 임시 경로), (경로, 크기, 수정 시각) 같으면 해시 재사용, `path_key` 해시도 저장(`reveal`용)
- [ ] 잠긴 파일·권한 오류 폴더는 `scan_errors`로 보고
- [ ] 흐름: config → runs → manifest → 업로드 → meta → complete, 1분마다 heartbeat, 판정 후 사라진 파일은 건너뜀, 업로드 실패는 재시도 큐
- [ ] 단일 인스턴스(이름 있는 뮤텍스, 테스트 가능하게 추상화)
- [ ] 프로토콜: `run`은 `source`만, `reveal`은 64자리 16진수 `k`만. 루트 안·제외 아님·존재하는 파일일 때만 `explorer.exe /select,<경로>`를 인자 배열로 실행(테스트에서는 실행기를 가짜로). 반복 호출 제한(`run` 1분 2회, `reveal` 10초 3회)
- [ ] CLI: `sync`, `status`, `install`(`--dry-run`이면 등록할 작업 스케줄러 설정과 레지스트리 키를 출력만), `uninstall`, `login`(keyring), `restore-info`
- [ ] 로그: `agent.log`(7일 순환), 토큰·본문 미기록
