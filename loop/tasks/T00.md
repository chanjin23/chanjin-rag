# T00 · 루프 기반: 테스트 DB, Fake Provider, 로그 규칙

## 목표

이후 모든 작업이 기대는 검증 기반을 만든다. 테스트용 ParadeDB를 `verify.sh`가 직접 띄우고, 모델 호출은 결정적인 Fake Provider로 대체하며, 로그 정책(질문 원문 미기록)을 코드에 반영한다.

## 근거

- TRD 2장(기술 스택), 3.2(컨테이너), 6.3(임베딩 호출), 11장(로그), 12.1(설정값), 14장(테스트 전략)
- CLAUDE.md 작업 완료 규칙

## 구현 항목

- [ ] `deploy/compose.test.yaml`: ParadeDB 공식 이미지(버전 고정), 포트 `5433`, 데이터는 tmpfs. pg\_search와 pgvector 확장을 초기화 SQL로 만든다
- [ ] `scripts/verify.sh`: pytest 전에 테스트 DB를 `docker compose ... up -d --wait`로 띄우고 `TEST_DATABASE_URL`을 넘긴다. 이미 떠 있으면 재사용한다. 기존 5단계는 그대로 둔다
- [ ] `verify.sh`: `LOOP_REPORT_DIR`이 있으면 pytest에 `--junitxml "$LOOP_REPORT_DIR/pytest.xml"`(이미 구현됨, 유지)
- [ ] pytest 마커 `samples`: 기본 실행에서는 빼고(`-m "not samples"`), `SAMPLE_DOCS_DIR`이 설정돼 있으면 `verify.sh`가 별도 단계로 `pytest -m samples`를 실행한다(`LOOP_REPORT_DIR`이 있으면 `pytest-samples.xml`)
- [ ] `backend/tests/conftest.py`: 테스트 DB 연결 픽스처(테스트마다 트랜잭션 롤백 또는 스키마 초기화)
- [ ] `app/core/config.py`: TRD 12.1 설정값 전체를 pydantic-settings로 정의(`PROVIDER=fake|nvidia`, `EMBED_DIM` 기본 2048 포함)
- [ ] `app/providers/`: `LLMProvider`, `EmbeddingProvider`, `RerankProvider` 프로토콜과 Fake 구현. Fake 임베딩은 텍스트 해시 기반의 결정적 벡터(같은 텍스트 → 같은 벡터, `EMBED_DIM` 차원), Fake LLM은 스트리밍 토큰과 고정 규칙 응답, Fake 재정렬은 토큰 겹침 점수
- [ ] 로그 정책: `LOG_QUERY_TEXT`가 false면 `chat.message.received`에 질문 원문 대신 길이만 남긴다. E2E는 `LOG_QUERY_TEXT=true`로 실행
- [ ] E2E 백엔드가 `PROVIDER=fake`, `TEST_DATABASE_URL` 기반 DB를 쓰도록 `playwright.config.ts`의 env를 정리(기존 JSON 리포터 설정은 유지)
