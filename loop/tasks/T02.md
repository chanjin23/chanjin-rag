# T02 · 인증: 세션 로그인, 잠금, CSRF, 로그인 화면

## 목표

웹은 단일 계정 세션 로그인, Sync API는 Bearer 토큰으로 보호한다. 로그인 화면과 세션 만료 시 입력 보존까지 만든다.

## 근거

- PRD 7장(보안), TRD 5.2, 8.1, 9.1(`/login`), 9.2(API 호출, 입력 보존), 11장(웹 세션, CSRF, 비밀번호, Agent 토큰)

## 구현 항목

- [ ] `/api/auth/login|logout|me`: argon2id, 32바이트 난수 `sid` 쿠키(`HttpOnly`, `Secure`, `SameSite=Strict`), DB에는 SHA-256만, 14일 슬라이딩 만료
- [ ] 5회 실패 시 15분 잠금, 잠금 중 `retry_after_s` 반환
- [ ] CSRF: GET이 아닌 요청에 `X-Requested-With`와 `Origin` 검사
- [ ] 웹 API 의존성(세션 필수)과 Sync API 의존성(Bearer 토큰, `revoked_at` 확인, `last_used_at` 갱신)
- [ ] CLI: `create-user`, `reset-password`, `create-token`(평문 토큰은 발급 시 한 번만 출력)
- [ ] 기존 채팅 API를 세션 필수로 바꾼다
- [ ] 웹: `/login` 화면(잠금 남은 시간, 비밀번호 분실 안내), 401이면 입력 중인 질문을 `sessionStorage`에 보존하고 로그인 후 원래 화면으로 복귀
- [ ] E2E: 테스트 사용자를 만들고 로그인 상태(storageState)를 공유해 기존 E2E도 통과하게 한다. 로컬 HTTP에서도 쿠키가 동작하도록 `Secure` 처리 방식을 설정으로 둔다(운영은 항상 Secure)
