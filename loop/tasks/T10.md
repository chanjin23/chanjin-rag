# T10 · LangGraph 질의 그래프와 SSE 연결

## 목표

스텁 채팅 API를 실제 질의 그래프로 바꾼다. 경우별 SSE 이벤트 순서, 오류 코드, 동시 요청 409, 연결 끊김 처리, 질의 로그를 TRD대로 구현한다.

## 근거

- PRD 5.2, F-08, F-09, TRD 7.1(그래프, 노드 표, 요약 대상 판정, 검색 범위, 답변 후처리), 7.3(SSE 이벤트, 경우별 순서, 오류 코드), 7.4, 5.3(`messages`, `query_logs`)
- CLAUDE.md: SSE를 바꿀 때 `backend/app/api/chat.py`와 `web/src/api/chat.ts`를 함께 고친다

## 구현 항목

- [ ] 노드: rewrite(이력 없으면 LLM 생략, JSON 파싱 실패 시 원문), retrieve(T09), rerank(`RERANK_ENABLED`), grade, retry\_rewrite(1회), generate(인용 번호, 자료 구분자, 프롬프트 인젝션 방지 지시, 수정일 언급, 질문 언어), summarize(map-reduce, 진행률), not\_found(coverage + 후보 3개), log
- [ ] 요약 대상 판정 표 5가지 경우
- [ ] 필터 결과 0개·문서 0개 안내
- [ ] 답변 후처리: 없는 인용 번호 제거, 추론 텍스트 제거
- [ ] SSE: `status`(`summarizing`·`progress` 포함), `sources`(`document_id`, `mtime`), `token`, `done`(`coverage`), `error`(`retryable`), TRD 7.3 경우별 순서표 준수
- [ ] 오류 코드 표의 6가지(`rate_limited`, `provider_unavailable`, `provider_auth`, `timeout`, `conflict`, `internal`)
- [ ] 같은 대화에 `streaming` 메시지가 있으면 409, 2분 넘은 `streaming`은 `aborted`로 정리
- [ ] 연결 끊김 시 생성 중단 + `aborted` 저장, 오류 시 `error` 저장
- [ ] `messages`·`query_logs` 저장(`coverage`, 단계별 지연, 모델명)
- [ ] 웹 `src/api/chat.ts`·`useChatStream`·채팅 화면의 타입과 단계 라벨을 새 이벤트에 맞춤(화면 기능 확장은 T11)
- [ ] Fake Provider로 시드 문서에 대해 결정적으로 동작하는 E2E(시드는 T06의 `ingest-local`)
- [ ] 로그: `chat.message.received`, `chat.message.completed`, `chat.message.not_found`, `chat.message.failed`
