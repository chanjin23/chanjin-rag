# T04 · 문서 파서: PDF, DOCX, PPTX, TXT, MD

## 목표

형식별 파서가 공통 `Section` 목록을 돌려주고, 실패는 사유 코드로 기록되며, 파싱은 하위 프로세스에서 타임아웃·메모리 상한과 함께 실행된다. 이번 작업은 PDF·DOCX·PPTX·TXT·MD 5종이다.

## 근거

- PRD 5.1-4, F-04, TRD 3.4(파서 표, 실패 사유 코드, `no_text`), 11장(파서 격리)

## 구현 항목

- [ ] `Parser` 인터페이스, `Section(location, heading_path, text, kind)`, 확장자 → 파서 등록표(대소문자 무시)
- [ ] PDF(PyMuPDF): 페이지 위치, 텍스트 레이어 없는 페이지는 "스캔본 의심" 경고 후 건너뜀, 암호 PDF는 `encrypted`
- [ ] DOCX(python-docx): Heading 스타일로 제목 계층, 표는 행 단위 `kind=table`(첫 행을 헤더로)
- [ ] PPTX(python-pptx): 슬라이드 번호, 제목→본문→표→발표자 노트 순서
- [ ] TXT·MD(charset-normalizer): cp949 판별, 줄 범위, MD 제목 계층
- [ ] 실패 사유 코드: `encrypted`, `corrupted`, `timeout`, `memory`, `parser_error`. 추출 텍스트 0자면 `no_text` 결과
- [ ] **아직 지원하지 않는 형식**(`.hwp`, `.hwpx`, `.xlsx`): 파싱을 시도하지 않고 사유 코드 `unsupported_format`(화면 안내: "이 형식은 아직 지원하지 않습니다. 후속 버전에서 지원합니다")을 돌려준다. T06은 이 경우 문서를 `failed`로 기록하되 파일명 청크 1개를 만들어 파일명 검색은 되게 한다. TRD 3.4 실패 사유 표에 이 코드를 추가한다
- [ ] 하위 프로세스 실행기: 60초 타임아웃, 메모리 상한(Windows 개발 환경에서도 동작하는 방식으로, 불가하면 이유를 기억 파일과 TRD에 기록)
- [ ] 샘플 테스트(`samples` 마커): `SAMPLE_DOCS_DIRS`의 모든 폴더를 순회해 지원 형식(MD·PDF·TXT·DOCX·PPTX)을 파싱하고, 형식별 성공률을 출력한다. 실패가 있으면 사유 코드가 붙는지 확인한다. DOCX·PPTX 샘플은 각각 1개 이상 있어야 하며 섹션이 1개 이상 나와야 한다. 샘플 내용(문장, 파일명)은 테스트 코드·스냅샷·로그에 남기지 않는다(개수와 비율만)
- [ ] 합성 픽스처: 정상 DOCX·PPTX(제목 계층, 표, 노트 포함), 암호 PDF, 손상 파일, 빈 문서는 테스트 안에서 생성(`tmp_path`)
