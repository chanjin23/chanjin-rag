# T04 · 문서 파서 7종

## 목표

형식별 파서가 공통 `Section` 목록을 돌려주고, 실패는 사유 코드로 기록되며, 파싱은 하위 프로세스에서 타임아웃·메모리 상한과 함께 실행된다.

## 근거

- PRD 5.1-4, F-04, TRD 3.4(파서 표, 실패 사유 코드, `no_text`), 11장(파서 격리)

## 구현 항목

- [ ] `Parser` 인터페이스와 `Section(location, heading_path, text, kind)`
- [ ] PDF(PyMuPDF): 페이지 위치, 텍스트 레이어 없는 페이지는 "스캔본 의심" 경고 후 건너뜀, 암호 PDF는 `encrypted`
- [ ] DOCX(python-docx): Heading 스타일로 제목 계층, 표는 행 단위 `kind=table`
- [ ] XLSX(openpyxl read-only, data\_only): 시트·행 범위, 첫 비어 있지 않은 행을 헤더로, 계산값 없으면 수식 문자열 + 경고
- [ ] PPTX(python-pptx): 슬라이드 번호, 제목→본문→표→발표자 노트 순서
- [ ] HWPX(zipfile+lxml): 구역·문단, 표
- [ ] HWP(pyhwp 계열): 문단 위치. 실제 HWP 샘플이 없으므로 손상 파일·미지원 상황의 실패 코드와 파서 연결만 검증
- [ ] TXT·MD(charset-normalizer): cp949 판별, 줄 범위, MD 제목 계층
- [ ] 실패 사유 코드: `encrypted`, `corrupted`, `timeout`, `memory`, `parser_error`. 추출 텍스트 0자면 `no_text` 결과
- [ ] 하위 프로세스 실행기: 60초 타임아웃, 메모리 상한(Windows 개발 환경에서도 동작하는 방식으로, 불가하면 이유를 기억 파일과 TRD에 기록)
- [ ] 샘플 테스트(`samples` 마커): `SAMPLE_DOCS_DIR`의 MD·PDF·TXT를 모두 파싱해 성공률을 출력하고, 실패가 있으면 사유 코드가 붙는지 확인. 샘플 내용은 테스트 코드나 스냅샷에 복사하지 않음
- [ ] 합성 픽스처: DOCX·XLSX·PPTX·HWPX·암호 PDF·손상 파일은 테스트 안에서 생성
