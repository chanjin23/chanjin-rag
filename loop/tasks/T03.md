# T03 · NVIDIA Provider 구현과 재시도

## 목표

T00의 Provider 프로토콜에 맞춰 NVIDIA 구현을 만든다. 실제 API는 부르지 않고 httpx 목으로 요청 형식과 재시도를 검증한다.

## 근거

- PRD 3장(모델), TRD 2장(모델 호출), 6.2(재시도), 6.3(임베딩 호출), 7.1(답변 후처리: 추론 텍스트 제거), 12.1

## 구현 항목

- [ ] LLM: openai SDK(`base_url`=NVIDIA), 스트리밍, `temperature`·`max_tokens` 설정값, 추론(thinking) 텍스트 제거
- [ ] 임베딩: `input_type=passage|query`, `truncate=END`, `modality=text`, `encoding_format=float`, **`dimensions=EMBED_DIM`**(모델 기본 4096차원은 halfvec HNSW 한도 4000을 넘음. 2026-11-07 API 문서 확인: `dimensions` 1~4096 지원, 입력 최대 10,240토큰), 배치(`EMBED_BATCH_SIZE`, 기본 1: 무료 엔드포인트는 묶음 요청에 500을 돌려줌. 묶음이 500이면 반으로 나눠 재시도), 응답 차원이 `EMBED_DIM`과 다르면 명확한 오류
- [ ] LLM: 모델은 `nvidia/nemotron-3.5-lightning-30b-a3b`(TRD 13장 비교로 선정). `LLM_EXTRA_BODY`(JSON, 기본 `{"chat_template_kwargs":{"enable_thinking":false}}`)를 요청 본문에 그대로 합침(openai SDK의 `extra_body`). 모델에 따라 대기열이 길 수 있으므로 읽기 타임아웃은 설정값으로 두고 기본 180초
- [ ] 재정렬 요청 형식: `POST RERANK_URL`, 본문 `{"model", "query": {"text"}, "passages": [{"text"}], "truncate": "END"}`, 응답 `rankings[].index`·`logit`
- [ ] 인증 실패는 NVIDIA가 401이 아니라 403(`Authorization failed`)으로 돌려주므로 둘 다 `ProviderAuthError`로 변환
- [ ] 실제 API 호출 형식은 `scripts/check_nvidia.py`(사람이 키로 검증한 스크립트)와 맞춘다
- [ ] 재정렬: httpx로 `RERANK_URL` 호출, 요청·응답 형식 매핑
- [ ] 재시도: 429·5xx·타임아웃에 tenacity 지수 백오프(최대 5회, 최대 대기 60초), 그 뒤에는 Provider 전용 예외(`RateLimited`, `ProviderUnavailable`, `ProviderAuthError`)로 변환
- [ ] API 키는 모델마다 다르므로 LLM은 `NVIDIA_LLM_API_KEY`, 임베딩은 `NVIDIA_EMBED_API_KEY`, 재정렬은 `NVIDIA_RERANK_API_KEY`만 읽는다(다른 모델의 키로 대신 호출하지 않음). 키가 없으면 해당 Provider 생성 시 명확한 오류, 로그에 남기지 않음
- [ ] `PROVIDER` 설정으로 Fake/NVIDIA를 고르는 팩토리
- [ ] 호출 결과를 `provider.call` 로그로 남김(모델, 지연, 상태 코드, 재시도 횟수. 본문 제외)
